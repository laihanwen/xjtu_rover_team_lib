# 八推全矢量 ROV 控制与安装说明

> 适用于 `MDK-ARM/Copy_cup.uvprojx`，更新日期：2026-08-30。机械构型采用 `(±180,±120,±58) mm` 近等姿态力臂方案；控制流程吸收 Gao 等 ICRA 2024 的“统一六维动力输入后单次分配”结构，并保留经典八推匹配增益。

2026-10-06 合并更新：T3=右前下、T4=左前下由用户确认；遥控与定深新行为见 [ROV 合并版 README](../../../tools/rov/README.md)。

## 1. 工程中的唯一有效源码

Keil 工程实际编译的自定义控制文件位于 `MDK-ARM`：

| 文件 | 职责 |
|---|---|
| `Move.c/.h` | 六维指令到八路逻辑推力的分配，遥控与舵机计算 |
| `Mate.c/.h` | 六维动力指令合成、单次动态缩放、极性应用与 PWM 输出 |
| `RC.c/.h` | 11 字节遥控帧到内部单向通道的转换 |
| `AuvRcInput.c/.h` | USART2 字节流组帧、一致快照与 250 ms 掉线保护 |
| `AuvMotionTarget.c/.h` | 树莓派运动目标校验、一致快照与 250 ms 超时 |
| `AuvControlSource.c/.h` | 每次 ARM 周期锁定 Pi 或遥控控制源，禁止运行中静默切换 |
| `PID.c/.h` | 位置式 PID |
| `imu.c/.h` | H30 IMU 帧解析与姿态角更新 |
| `Core/Src/usart.c` | UART1/2 接收中断 |

`Core/Src/Move.c`、`Core/Src/Mate.c` 等同名文件是历史副本，不在当前 Keil 编译链中。不应以它们为实机行为依据，也不要将新混控同时复制到两套目录。

### 1.1 编辑器 UI 与代码模型

- 实机固件始终以 `MDK-ARM/Copy_cup.uvprojx` 的 ARMCC5 编译结果为准。
- 根目录 `CMakeLists.txt` 提供 `rov_ui_model` 编译目标，仅用于 CLion、VS Code 和 clangd 的代码索引及编译期检查，不执行固件链接和下载。
- UI 模型使用 `ui-armclang` 预设，并与 Keil 保持相同的 30 个 C 编译单元、`USE_HAL_DRIVER`/`STM32F405xx` 宏及头文件路径。
- CLion 打开工程后选择 `STM32F405 UI model (Keil ARMClang)` 并重新加载 CMake；VS Code 会读取 `build/ui-armclang/compile_commands.json`。
- 若 Keil 不在常见的 `C:/D:/E:/Keil_v5`，应将环境变量 `KEIL_ROOT` 设置为实际的 `Keil_v5` 目录。

## 2. 本版本保持不变的接口

本次八推改造仅更改推力分配与其解释，以下项目保持原工程设置：

- 遥控帧格式、通道顺序和死区；
- 推进器 PWM 中位 `1488` 与逻辑偏差 `±450`；
- T1..T8 的定时器通道映射；
- `Motor_1Polarity` 至 `Motor_8Polarity`；
- PID 参数、Yaw/Depth 开关行为与舵机功能（2026105 合并后的映射见第7节）；
- 原 9/10 号附加推进通道始终输出中位，不参与混控。

## 3. 坐标系与方向定义

机体坐标系是以重心为原点的右手系：

- `+X`：向前；
- `+Y`：向左；
- `+Z`：向上；
- 安装坐标单位：毫米（mm）。

`Move.c` 中记录的方向 `d_i` 是推进器对 ROV 机体施加的正向力。机械安装时观察到的尾流喷射方向 `j_i` 与它反向：

```text
j_i = -d_i
```

控制分配矩阵必须使用机体受力方向 `d_i`，不能把尾流向量直接填入矩阵。

## 4. Gao 正交拓扑下的经典能力匹配构型

本版保留 Gao 构型的正交符号拓扑，但不直接照搬三轴等分量。方向比例由经典八推单轴能力与保留增益 `0.85、0.85、0.62` 联合确定，坐标再按近等姿态力臂条件确定：

```text
a = 0.180 m    b = 0.120 m    c = 0.058 m
p = |d_x| = |d_y| = 0.416699
q = |d_z| = 0.807913
```

`2p²+q²=1`，绝对分量对应与三个坐标轴的锐角为 `65.374°`、`65.374°`、`36.107°`。三个单推进器纯轴力矩系数为：

```text
|Mx| = b q + c p = 0.121118 m
|My| = a q - c p = 0.121256 m
|Mz| = (a + b) p = 0.125010 m
```

三个姿态力臂最大差异约 `3.2%`。由于八台推进器的正向机体受力均具有 `+X` 分量，纯前进时八台 T60 均使用正向高推力区。

## 6. 控制分配模型

第 `i` 台推进器对机体的作用列向量为：

```text
B_i = [d_i; r_i × d_i]
```

八路逻辑推力 `f` 产生的六维合力/力矩为：

```text
w = B f
w = [Fx, Fy, Fz, Mx, My, Mz]^T
```

物理配置矩阵的六行互相正交。使用上述米制坐标和单位受力方向构造 `B` 后有：

```text
rank(B) = 6
B B^T = diag(1.389105, 1.389105, 5.221791,
             0.117357, 0.117624, 0.125019)
```

非对角项为零，表示理想几何下六轴静态分配互不串扰。归一化伪逆的符号矩阵保留经典八推能力匹配增益：

```text
[Fx, Fy, Fz, Mx, My, Mz]
[0.85, 0.85, 0.62, 0.85, 0.47, 0.85]
```

运行时完整矩阵的八行依次为：

```text
T1  [0.85, -0.85,  0.62,  0.85, -0.47, -0.85]
T2  [0.85,  0.85,  0.62, -0.85, -0.47,  0.85]
T3  [0.85,  0.85, -0.62,  0.85,  0.47,  0.85]
T4  [0.85, -0.85, -0.62, -0.85,  0.47, -0.85]
T5  [0.85,  0.85, -0.62, -0.85, -0.47, -0.85]
T6  [0.85, -0.85, -0.62,  0.85, -0.47,  0.85]
T7  [0.85, -0.85,  0.62, -0.85,  0.47,  0.85]
T8  [0.85,  0.85,  0.62,  0.85,  0.47, -0.85]
```

六维 `60%` 输入限制已按机械与操控要求删除。遥控档位、PID 原有限幅以及最终 `1488±450` 电机范围继续提供边界保护；多自由度叠加超出电机范围时只执行一次公共动态缩放。

原始物理矩阵混合了牛顿和牛顿米，直接报告整体条件数没有工程意义；本工程只检查满秩、行正交、各轴能力和饱和余量。

这些关系成立的前提是位置、方向、电机编号和极性都与实机一致。

## 7. 遥控映射与档位

USART2 使用 PA2/PA3、115200 8N1。每帧共 11 字节，格式为
`0xA5, Ch0, Ch1, Ch2, Ch3, Ch4, Ch5, Ch6, Btn0, Btn1, Btn2`。
接收中断不会直接改写控制通道；完整帧由 `AuvRcInput` 发布，主循环取得一致快照后才调用
`RC_Translate()`。超过 250 ms 没收到完整帧时，运动通道清零，已 ARM 状态会被撤销。
再次收到遥控数据不会自动 ARM，必须重新通过显式 ARM 流程。

### 7.1 树莓派运动目标与控制源锁定

UART1 的 `MOTION_TARGET` 负载依次为 `sequence、vx、vy、depth、yaw`。
目标可在 DISARM 状态下预先缓存，但只有显式 ARM 成功后才参与控制。ARM 后首个
控制周期优先选择新鲜的 Pi 目标，否则选择新鲜遥控帧，并在本次 ARM 周期内锁定该
来源；锁定来源超过 250 ms 未更新时立即 DISARM，不能自动切换到另一来源。

当前 `vx/vy` 是开环 PWM 前馈，默认系数位于 `Mate.h` 的
`AUV_SURGE_PWM_PER_MPS` 和 `AUV_SWAY_PWM_PER_MPS`，必须在拆桨或约束水槽中标定。
`yaw` 使用现有 IMU 航向 PID。`depth` 已接入 STM32 定深控制；`AUV_DEPTH_CONTROL_CALIBRATED=0` 默认强制保持 `Fz=0`，尚未完成实机定深标定。
深度驱动接入边界已经固定为 `AuvLink_UpdateDepth(depth_m)`：输入必须是有限的米制正值，
超过 250 ms 未更新即自动失效。具体传感器、总线和标定参数仍须按实物确定，禁止用固定值
绕过 ARM 安全门。

## 8. 统一六维动力指令与单次分配

```text
遥控平移 ------------------> Fx, Fy, Fz --------\
横滚/俯仰姿态闭环 --------> Mx, My              > 统一 u_dyn
偏航直控或航向闭环（二选一）-> Mz -------------/
                                                    |
                              同一矩阵只分配一次 u_thruster
                                                    |
                                    八路统一公共动态缩放
                                                    |
                                      极性 --> PWM --> 电机
```

论文中控制器先得到唯一的六维动力输入 `u_dyn=[Fx,Fy,Fz,Mx,My,Mz]`，随后才通过配置矩阵转换为八台推进器输入。论文没有“PID 八路输出”和“遥控八路输出”两套电机量相加的步骤。

本工程现在遵循同一顺序：遥控只负责填写平移分量，姿态闭环只负责填写转矩分量，偏航根据开关在直控和闭环间二选一。形成完整 `u_dyn` 后仅调用一次 `VectorAllocate_Wrench()`。

当八路中任意一路超过 `±450` 时，八路使用同一个比例缩小到可行范围。这样会保持当前合成动力指令的六维比例，不再使用旧版“先保姿态、再压缩遥控”的两级叠加逻辑，也不会逐台独立裁剪而破坏方向关系。`constrain()` 只作为最后的数值保护。

必须明确：这里采用论文的正交全矢量拓扑、动力输入组织和分配顺序，并按经典八推能力调整了方向分量；没有复制论文的 60% 实验限制或完整 NMPC。论文完整控制器仍要求：

- 13 状态反馈：`[x,y,z,qw,qx,qy,qz,u,v,w,p,q,r]`；
- 当前机器人自己的质量、三轴转动惯量、六项附加质量和六项线性阻尼；
- RK4 离散化、有限预测时域、SQP 求解，以及 CasADi/acados 生成的求解器；
- 实验中为 Jetson Orin NX + ROS + 高频位姿/速度估计，优化频率 `20 Hz`，推进器执行频率 `50 Hz`。

当前 STM32 工程只有 H30 欧拉角，没有位置、线速度、角速度和完整四元数输入，也没有本机水动力辨识参数，所以仍使用现有姿态 PID 生成 `Mx/My/Mz`。完整状态和本机参数具备后，可以用 MPC 输出直接替换 `dynamics_wrench`，下游单次分配、动态缩放、极性和 PWM 层不需要再次改写。

## 9. T60-EDU 参数使用边界

用户提供的图片与规格可确认：额定电压 `24 V`、最大功率 `190 W`；曲线端点约为正向 `3.4 kgf`、反向 `2.5 kgf`，正反推明显不对称。图片只有功率—推力和转速—推力曲线，没有 PWM—推力原始数据，因此固件暂不伪造 PWM 反函数，也没有写入未经验证的正反补偿。

按照论文第 II-A 节，必须把 T60 固定在水下测力台上，同步记录每台推进器的 PWM、电压和推力，分别拟合正转/反转曲线、死区、迟滞与个体差异。得到原始标定表后，才可把当前线性逻辑计数安全替换为牛顿到 PWM 的查表反函数。

## 10. T35-L 单舵机夹爪

P13 夹爪信号固定使用 `PA8/TIM1_CH1`。TIM1 以 2 MHz 计数，因此
`CCR = pulse_us × 2`，周期 20 ms。脉宽增大张开，减小闭合。

实际开合端点保存在 `AuvGripperConfig.h`。`AUV_GRIPPER_CALIBRATED=0` 时关闭PWM并拒绝运动；标定后默认保持配置中间位置，不再开机自动走到关闭端点。

需要开机小幅动作时，设置已验证的 `BOOT_START_US`、`BOOT_EXCURSION_US`，同时启用 `AUV_GRIPPER_BOOT_TEST_ENABLED` 与标定门。启动位置→等待→限速移到自检位置→停留→返回启动位置，每次初始化仅执行一次。两位置都必须在实测开合端点内；无效配置禁用输出。STOP、漏水、急停或ARM会取消自检，远端运动命令在自检期间被拒绝。自检专用授权不ARM推进器。

这些位置是绝对PWM指令；无位置反馈舵机无法读取上电前真实角度，也不能保证首次到启动位置的移动很小。自检完成表示指令序列完成，不证明舵机实际到位或无卡滞。角度到PWM必须实测换算，不用通用500..2500μs假定机械限位。默认自检关闭，两个PWM均为TODO占位0。

## 11. 摄像头俯仰舵机

从“八推矢量_代码开发_可改_摄像”参考工程确认的信号通道为 `PC7/TIM8_CH2`，当前
`Copy_cup.ioc` 也配置为该通道。参考工程给出的候选范围是 CCR `2550..3100`，但该数值
尚未在当前摄像头连杆上完成机械端点验证，因此 `AuvCameraServoConfig.h` 默认设置
`AUV_CAMERA_SERVO_CALIBRATED=0`。此状态下不启动 TIM8_CH2 PWM，Pi 和遥控转动命令均被拒绝。

完成断开推进器电源的实机标定后，才能修改最小/最大/启动 CCR 并启用标定门。运行时每个
10 ms 控制周期最多变化 `AUV_CAMERA_SERVO_SLEW_PER_TICK`，DISARM 会立即冻结当前位置。
遥控状态下 `SB=0` 使用 SA 调节摄像头，`SB=1` 仍控制夹爪；Pi 使用执行器 ID `2`，并且
仍须满足 ARMED、Pi 控制源锁定和递增命令序号。

## 12. 实机安装后的必做检查

1. 拆除或隔离其他推进器，每次只以低功率驱动一台。
2. 核对实机编号与第 5 节的 PWM 通道。
3. 在逻辑正指令下核对尾流方向与第 4.2 节一致。
4. 依次进行纯 `Fx/Fy/Fz/Mx/My/Mz` 低功率测试，确认非目标轴无明显动作。
5. 单轴正确后再进行双轴和三轴叠加，同时记录 IMU、公共缩放比例和八路 PWM。

本版只适用于安装位置 `(±180,±120,±58) mm` 与第 4 节所列尾流方向同时成立的情况。若实际位置、重心或尾流角度改变，应根据最终实测的 `r_i` 与 `d_i` 重新生成配置矩阵、伪逆和经典匹配增益。
