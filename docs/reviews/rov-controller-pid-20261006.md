## 优先排查的控制问题

### 1. 两份源码的反馈系数和电机极性不一致

| 参数 | 当前仓库 | 当前桌面 MDK-ARM 源码 |
|---|---|---|
| pit_xishu | +2 | -2 |
| roll_xishu | +1 | -1 |
| T2、T3 polarity | -1、-1 | +1、+1 |
| 主推中位 | 1488 | 1492 |
| yaw PID P/I/D、限幅 | 3/0/0.02、±100 | 3/0/0、±400 |
| pitch PID P/I/D、限幅 | 5.5/0/0.01、±400 | 5.5/0/0、±400 |
| roll PID P/I/D、限幅 | 5/0/0、±200 | 5/0/0、±400 |

桌面注释称负系数用于修正正反馈，但注释不构成当前实物安装验证。错误的反馈符号或电机极性会影响纠正方向及轴间耦合；不能只通过降低 P 修复。先确认板上版本，再记录 IMU 正方向与对应 T1..T8 预期输出，最后在允许的安全条件下验证实物方向。此轮没有复制桌面符号或中位值。

### 2. 横滚角过零/跨 ±180° 时存在单边归一化缺口

`imu.c` 使用当前角减首次角作为姿态；roll 仅把 [180,360] 减360，没有处理负侧越界。例如首次 +179°、当前 -179°，代码结果 -358°，实际最短差为 +2°。仓库横滚 P 项会由约 -10 跳到 +1790，再被限为 +200，可能触发明显的错误纠正。Yaw 最短误差在 Mate.c 已处理；pitch 不能未经 Euler 约定核对就套用同一包角规则。该问题只证明特定边界错误，不能解释全部轴的所有工况。

首次有效姿态还会作为零点。如果上电时机器人有倾斜，控制目标0对应的是上电姿态，而不是经测量的水平姿态。

### 3. 姿态控制基本以 P 为主，输出变化没有独立斜率限制

仓库 pitch 输出乘2后才混控，因此实际 P 比例为11，最大俯仰动力指令±800；纯俯仰分配系数0.47，对应单电机偏移最多±376。10°俯仰静态误差对应约±51.7中位偏移（按当前矩阵、仅该轴计算，不代表实际水下力）。roll、yaw分别限幅±200、±100。总混控±450公共缩放会保持比例，但不限制每周期变化速度。

`PID.c` 的微分为每次误差差分，没有除实际 dt；积分为每次误差累加，没有乘 dt。现有姿态 I 全为0，因此不能把当前姿态问题归因于积分饱和。roll D 为0，其余 D 也很小；控制器没有读取角速度作为独立阻尼项。不能直接把 D 改为按秒计算而保留原参数，否则尺度会改变。

`Mate_Task` 每轮 Delay(10)，实际周期还包含计算/处理时间，却用固定0.01秒增加 yaw 目标；姿态 PID 每轮计算，不按新的 IMU 样本触发。需要采集实际周期、IMU采样间隔、目标/角度/输出与饱和记录，才能判断震荡、传感器更新或方向问题。

### 4. 当前部署与“深度 PID 过激”的描述需要核对版本

仓库默认 `AUV_DEPTH_CONTROL_CALIBRATED=0`，定深输出为零。树莓派 ROV 服务仍为预览，轻量串口为空，没有实际 heartbeat/ARM。若现场深度闭环正在输出，需首先确认板上是否运行桌面旧固件、其他参数分支或另一控制入口。不要为了排查而绕过安全门。

### 实际运行的 PID

先确认桌面 AXF 的 Flash LOAD 段与读回一致，再使用该 AXF 符号读取 RAM。约9秒内读取30组，MCU保持 RUNNING；没有停核，字段并非原子快照，不能据某组细微 Pout/OutPut差异推断计算错误。记录见 [PID只读采样](pid-live-readonly.json)。

实际参数：pitch P=5.5、I=D=0、输出±400、外乘-2；roll P=5、I=D=0、输出±400、外乘-1；yaw P=3、I=D=0、输出±400；depth P=300、I=1、D=0、输出±400。因此现场姿态环确实是纯P控制，而不是仓库带少量D的版本。姿态积分虽累计到100，但 I=0、Iout=0，**不是当前姿态过激的积分原因**。

本次静止状态：pitch/roll/yaw误差约0.14..0.36°，姿态PID输出约0.69..1.13，深度输出0；T1..T8 CCR读数1490..1493。没有复现用户反馈的大幅响应，不能宣布整定成功。IMU零点为首次数据记录，当前深度读数约-0.22m，需检查零点和深度有效性。

确认的旧版问题：

- 开机中位等待2秒结束后，没有显式ARM门，pitch/roll会在没有遥控输入时继续纠正；本次 CCR 与中位有1..2计数差即为实际证据。旧版也没有仓库的遥控/传感器超时安全链路。
- 航向保持微操用 `MyRCKey[2]-MyRCKey[1]`，直接偏航用 `[1]-[2]`，打开模式后摇杆作用方向相反。仓库合并版已改为一致。
- 旧版 depth PID 每次约10ms任务调用都积一次误差，不按新样本推进，也不乘实际dt；名义KI=1相当于约每秒100次累加。需要按米·秒重定义参数，不能直接照搬其KI。仓库已实现新样本/实际dt和防饱和，默认标定门关闭。
- 旧版遥测发送被注释，PC界面初始化成0也不代表实际姿态为0；Pi当前服务为预览（无 `--forward`，PrivateDevices=yes），轻量serial=false、heartbeat=0。因此这次PC采样没有进入STM32，不能把按键变化当作端到端通讯验收。

反馈方向、单电机极性及真实水下震荡仍需在断电/安全条件下分别验证。根据当前证据，不应只降低P后直接烧录；应先确认逐项遥控映射与负反馈方向，再准备输出限幅/斜率及阻尼的候选方案。

## 惯导间歇性冻结的处理（2026-10-06）

用户补充现象：有时无法回传/处理惯导角度，导致PID失效。以下代码缺陷已经确认，现场间歇性触发原因仍需错误计数与长时采集定位。

- USART1 460800逐字节IT接收，原回调先完成校验和/欧拉角解析，再重启接收。已改为先复制当前字节、立即重新武装，再解析；缩短RX关闭窗口，但不是DMA改造，仍需关注高负载ORE。
- 原重启返回值未检查。新增 `imu_uart_errors`、`imu_rx_restart_failures`；主循环在RxState READY时短临界区重开接收，保留正在工作的BUSY接收。
- 原错误回调对所有错误都重置接收索引，PE/FE/NE非阻塞错误可能仍有旧地址上的活动接收。改为固定单字节地址，错误时复位解析器，仅READY时重开。
- 原解析器没有断帧超时，重复0x59会丢失下一帧头。新增纯C组帧器：20ms字节间隙复位、坏校验后保留候选帧头再同步；新增校验失败和断帧超时计数。20ms是软件恢复间隙参数，不改变惯导输出配置；断帧会丢弃，不会生成角度。
- PID原来读取ISR逐个更新的全局角度，可能混用不同帧。现在在短临界区取三轴一致快照；距最后有效角度超过250ms即DISARM并清零姿态PID积累及输出，不用旧角度继续纠正。
- 新鲜度现在由接收有效欧拉角时的 `imu_last_sample_ms` 决定，独立于遥测发送调度；状态遥测过期输出NaN。UART接收恢复不会自动ARM。
- 未使用的 `h30_bytes_to_float` 把整数位型当float的错误也已修正为有符号微度数值转换；它不在当前角度主链路中，不能当作本次冻结原因。

区分回传与闭环：板上旧版遥测发送被注释，Pi与STM32实际接USART2，而仓库AuvLink在USART3。上位机没有角度并不证明IMU接收停止。上述代码不会自动改变USART用途，也未发送惯导配置或控制指令。Core/Src/imu.c是未编译的旧副本，实际Keil/CMake均编译MDK-ARM/imu.c，本次修改生效源文件为后者。

验证：组帧回归覆盖重复帧头、坏校验后好帧、断帧超时恢复；STM32宿主测试11/11，Keil编译0错误0警告。测试不覆盖真实UART中断时延、线路干扰或水下PID稳定性；尚未烧录，板上仍为旧版。

本轮尝试以无线CMSIS-DAP只读监测旧版角度、USART1 SR/CR1及接收索引时，发生 `SWD/JTAG communication failure (Unexpected ACK 0)`，采样中断，未形成有效完整报告。不能据此认定惯导故障或排除间歇性冻结；该错误发生在调试链路。未进行目标复位、擦除或烧录。
