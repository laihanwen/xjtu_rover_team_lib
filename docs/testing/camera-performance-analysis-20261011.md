# 双摄低帧率离线分析

日期：2026-10-11。依据本地备份 `build/camera-diagnostics/20261011/`，约 18:12 的设备只读快照、当日服务日志及内核日志。未修改配置、重启服务或部署代码。

## 实测与判断

| 证据 | 结果 | 判断边界 |
|---|---|---|
| `get_throttled` | `0x50005` | 当前欠压及节流，同时保留历史标记 |
| ARM 时钟 | 约 600 MHz | 采样时已降频，不代表整个会话恒定频率 |
| 内核日志 | 多次 Undervoltage detected / Voltage normalised 交替 | 供电不稳有直接证据；具体是电源、线材或接头尚未确定 |
| Runtime CPU | 约 293%，另 CSI 进程约 37% | 多核处理负载高；进程占用是 ps 统计，不是逐段耗时 |
| 内存 | 约 490–508 MiB 使用，约 3.2 GiB 可用，交换为零 | 未见内存不足证据 |
| 温度 | 约 55°C | 本次直接证据指向欠压，不能将降频全部归于过热 |
| Runtime 状态 | 下视约 16.25 Hz、前视约 14.15 Hz，视觉约 11.08 Hz，视觉延迟 p99 约 198 ms | 状态中的速率为平滑统计，非相机硬件原始帧率 |
| Pi 本地快照访问 | 约 5 秒内下视缓存变化约 77 次、前视约 71 次；平均请求耗时约 4–5 ms | 高频请求有额外负载；缓存头变化仅辅助印证约 14–15 FPS，不用于正式性能验收 |
| eth0 | 1 Gbps 链路，累计错误/丢包计数为零 | 不证明 PC 代理、浏览器或端到端网络绝无瓶颈，但低速已出现在 Pi 缓存层 |

优先结论：Pi 当前欠压降频是已确认的问题，叠加双摄 640×480 矫正、编码与视觉处理，最可能使两路输出一起降速。尚不能量化各因素贡献，也不能承诺处理后达到 30 FPS。

## 实际运行版本与配置

服务有 `/run/systemd/system/auv-runtime.service.d/91-front-resolution-test.conf` 覆盖，实际运行 `/usr/local/bin/auv_runtime /run/auv-front-resolution-test/runtime.yaml`；另有 AWB 试验 PATH 覆盖。不能仅查看 `/etc/auv-runtime/runtime.yaml` 判断实际入口。

双摄均为 640×480、请求 30 FPS、矫正预览开启。前视来自 USB，下视来自 CSI；HLS 视频、定位和机载 recording 当前关闭，串口为空、运动与自动启动关闭，任务保持 INIT。故本次没有证据将低帧率归因于自主定位或机载录像。PC 录像是否同时开启不在快照中证明。

当前本地代码路径显示：

- 下视 CSI JPEG 解码后矫正，再编码矫正 JPEG；原始 JPEG 可复用。
- 前视 USB 解码后矫正，同时编码原图和矫正 JPEG，即使没有原图客户端也会生成原图缓存。
- 视觉循环在 INIT 仍可调用 GridMapper，不以 ROV 纯采集用途跳过处理。
- 矫正映射表已预计算，不应再把“每帧重复计算内参映射”当成原因。
- 本地有 OpenCV 单线程默认配置，但备份没有生产二进制对应提交号/线程信息，不能宣称该优化已生效。

以上代码审查是优化候选；生产二进制对应关系与各阶段计时尚不足，不能将候选开销称为已确认的耗时比例。

## 建议执行顺序

1. 恢复设备后先检查供电链路，分别观察空闲、单摄及双摄负载下的欠压当前位与时钟，排查电源、连接线及接头；不通过软件隐藏欠压告警或强制频率绕过问题。
2. 给纯 ROV 摄像头配置明确的感知关闭/按任务阶段启用开关，保留预览与双摄录像。不要仅以“运动关闭”推断算法无需运行，避免改变 AUV 观测行为。
3. 增加采集、解码、矫正、原图编码、矫正编码、缓存发布的计时，以及实际协商格式、帧序号与丢帧指标；核对生产提交号和 OpenCV 线程数。
4. 在匹配内参的固定分辨率下做原图/矫正双摄对照，比较资源和新帧速率；不通过随意缩放内参换性能。减少无人使用的重复编码时须保留 PC 原图录像及元数据能力。
5. 若仍受限，再分离采集与耗时处理，用有界最新帧队列并显式记录跳帧；预览与录像的质量、帧率策略分别配置，不让慢算法阻塞取帧。
6. 最后测 Pi 本地输出、PC 接收、浏览器呈现和录制帧数，确定剩余瓶颈；需要服务重启的实测先核查安全与录像状态。

本地已保存事件轮转日志、系统日志、生效配置、状态与 SHA256 清单。未要求 Pi 持续在线。下一步可先开发纯摄像头模式和耗时诊断，待供电恢复后做对照实测。
