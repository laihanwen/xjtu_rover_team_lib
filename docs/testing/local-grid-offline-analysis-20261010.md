## 现有算法的边界

`GridMapper::process` 必须先找到完整闭合外框，再做黄边规范化和整图透视变换。`metric_grid_pose` 使用该外框四点与固定世界四角做 PnP。现有多帧稳定确认没有累积不同视野的局部子图；下视平面里程计也没有替代绝对网格关联。

注意 `metric_grid_pose` 中 `abs(down[2]) < 0.8` 检查的是经外参转换后的机体相对地板姿态，不能仅因前视俯角 45° 删除该门。相机安装倾角与机体倾斜不同。

## 建议路线：局部网格观测＋短时里程计＋地标修正

不再要求每帧或某一帧拍全图，仍要求足够可关联的局部几何与观测覆盖。

1. **建立局部参考系**：标签提供可重复锚点；首次看见黄色边时确认网格方向。标签相对网格的位置尚未知，不能把 ID18 自动设成某格中心。未确认黄边时保留多种旋转/格位假设，不输出唯一格号。
2. **观测局部结构**：检测真实网格管、T/L/十字接头与局部闭合单格，结合名义 820 mm 格距提出节点关联。与瓷砖线的区分需要颜色/管宽/接头形状和时序一致性，不能只按平行线间距筛选。
3. **关联后求绝对修正**：四个已知、分布良好、非共线的局部平面节点可用于单应性或平面 PnP；不必是九宫格外框四角。关键是节点全局编号正确，重复网格的一格平移与 90° 歧义须拒绝。少量点或一条线不足时，仅保留约束，不伪造完整位姿。
4. **短时补偿观测间隙**：复用下视地板光流及 IMU、深度，记录帧龄、残差、累计漂移和不确定度；前视/下视的新地标重新修正。高度、同步和图像空间未经验证时不能将光流转成可信米制位移。长时间无锚点应停止推进并报告定位失效。
5. **累积语义地图**：每格保存已观测覆盖、锥类别投票、底座位置、轮廓及参考帧；未知不当空。先局部观测扫描并确认四目标，再冻结地图规划 24 种访问顺序。类别不能仅看方底；锥尖不能当底座落点。
6. **阶段重定位**：上浮后废弃旧阶段有效位姿，使用新阶段成像模型与新局部地标重新关联。继承的是带证据的地图，不是旧相机位姿。无法得到唯一关联则保持未就绪。

OpenCV 平面几何与 PnP 的基础见 [单应性](https://docs.opencv.org/4.10.0/d9/dab/tutorial_homography.html)、[PnP](https://docs.opencv.org/4.11.0/d5/d1f/calib3d_solvePnP.html)。上述为工程方案，尚未实现或验收局部节点关联与融合。

## 下一轮开发与数据

优先离线输出真实网格管/接头候选及分类证据，在现有片段人工核对瓷砖误检、局部单格和跨帧重复关联，再实现便携核心局部地图累积与故障测试。不直接修改 Runtime 的完整四角安全门来放行。

后续采集应关注相邻视野有重叠、局部接头清晰、黄边出现片段、四锥分别从侧面/上方观测，以及回到同一地标的闭合片段。保留原始双摄录像、帧索引与同步遥测；剪辑前后不能假定时间连续。无需为全图或现有水下标定重新拍摄。

深度计位置已由用户确认为机体中心坐标 `[-0.16, 0.02, -0.05] m`，同步硬件记录与 Runtime 模板。水平姿态下传感器比机体中心低 5 cm；倾斜时按姿态旋转修正，不能总加减 5 cm。此位置确认不等于深度零点、池底深度或导航整体标定通过，运动门保持关闭。
