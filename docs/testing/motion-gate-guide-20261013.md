# 运动门测试辅助页

入口 `/dashboard/motion.html`。已部署 HTML/JS，复用几何页样式；不需要编译或烧录，不改变 Runtime 配置。页面仅 GET 状态，不发送 ARM、运动、急停或参数写回命令。

先保持 DISARM 记录基线，再选择观察方式、确认机体受控固定及现场断电条件，点击开始观察；实际操作通过已有已验证控制入口或无推力手动移动完成，选择操作者实际观察和备注后结束保存。逐项完成前进、后退、左右、升降与停止，导出 motion-gate-*.json。

动力观察要求当前遥测新鲜、已ARM、运动许可和MCU安全门均已通过；未满足不能以本页打开控制。无推力观察要求 DISARM，与动力观察分开记录。运行会话变化、遥测失效或无推力观察中出现ARM使记录作废；旧会话基线不能用于新会话。采样有上限，保存当前目标、深度、独立压力序号/年龄、姿态和状态。

升降方向检查仅使用不同压力序号的有效样本，变化不足3 cm不下方向结论；不能用手动搬动数据证明推进器极性。水平位置缺乏可信反馈时仅保存操作者确认，不自动推断速度、推力增益或PID通过。当前接口无八路PWM，命令为零不证明实际推进器停止。本页不把观察记录标成完整动力验收或自动打开生产门控。

增量验证：JS语法、DISARM基线、动力许可拒绝、无推力记录、会话失效检查通过；实机浏览器显示新鲜遥测、有效深度约0.7 m、基线可记录、动力观察禁用；窄屏无横向溢出。状态时刻值不替代后续实时检查。本地部署证据及深度采样位于 build/auv-entry/motion-test/，未重跑全量测试、未发送START/ARM。
# 受限点动驾驶台（新增使能入口）

在 PC 仓库根目录执行 `./tools/rov/Start-RovTrial.ps1 --motion-test`，打开 http://127.0.0.1:8767/ 。此启动仅运行 PC 控制程序，不烧录或切换 Pi 服务。

前置条件是独立 ROV 固件及 `auv-rov` 串口桥；停止占用同一 UART 的 AUV Runtime，使用匹配的 ROV 摄像头服务。不能只切换 Pi 服务来控制 AUV 固件。设备服务、固件切换与实际动作须另行执行，目前新增源码未部署、未实机验收。

1. 岸上放平并保持 DISARM，勾选确认后点“采集校平”，等待校平状态通过。
2. 确保机体受控、桨区无人，保持遥控器实体安全许可开关，点“显式 ARM”。以收到的 ARM 遥测为准。
3. 按住一个方向按钮观察，固定低档、RC 偏移 32；正负为控制坐标符号，不预先宣称实物方向。沿用 ROV 姿态、航向及深度保持逻辑，因此单轴指的是目标通道，不是只有一个推进器输出。
4. 松手、切出页面、浏览器刷新中断、失联或许可撤销均结束点动；PC 将发送 STOP/DISARM。单次超过 1 秒在控制循环中锁止并 STOP；刷新不能延长该上限。下次先释放按钮，再显式 ARM。

页面只在新鲜遥测、已 ARM、实体许可同时满足时开放点动。正常摇杆运动在此专用模式被忽略；保留实体许可输入。Pi 挑战租约、序号检查、通信超时与 MCU 保护继续生效。软件 STOP 不替代现场断电，PC 循环卡死时由既有 Pi/MCU 超时保护停止。

本次增量验证：`test_motion_jog.py` 3 项（绝对时限、刷新失效、实体许可失效、单轴和非法请求）；`test_trial.py` 10 项既有租约/串口桥回归，以及 Python 语法检查。未执行全量构建；未改变 MCU 固件及自主标定门。
