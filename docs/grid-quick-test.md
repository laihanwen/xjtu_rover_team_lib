# 九宫格建图与遍历快速测试

使用现有 `a2_task_one`，不使用标签停靠入口启动九宫格任务。代码已包含局部建图、多帧覆盖、上浮、重定位、四锥遍历与退出；最新局部正常闭环仍失败，不能视为已具备实机自主运行条件。

## 现在可执行：完整 Linux 模拟

使用已有完整构建目录；缺少测试注册会明确失败，不将零项测试当作通过。以下命令兼容 fish：

```fish
cmake --build build/task-one-ubuntu-20261012 -j 3
python3 tools/auv/grid_test.py --build-dir build/task-one-ubuntu-20261012
```

`--scope mapping` 只跑局部建图闭环，`--scope traversal` 独立跑下游分段，`--list` 仅检查注册列表。默认跑局部闭环、下游分段、完整外框参考和退出参考；失败后继续其他案例，最终返回非零状态。证据在 `build/grid-test/<UTC时间>/`。分段前置地图来自合成真值，只能说明对应阶段，不能替代完整建图验收。

## 设备修复后：实机准备顺序

1. 推进器动力断开，确认当前 MCU 固件和 Pi 服务；ROV 与 AUV 串口控制不能同时运行。
2. 使用 `runtime/config/pi-auv-task-one.yaml` 作为实测配置模板，不沿用 tag_docking 的任务命令。新模板默认空串口、禁用运动和自动 ARM。
3. 放平校准 IMU；以水面压力读数确定绝对深度零点。受限、低输出条件下确认自主升沉纠正方向、surge/sway 增益，填写 `AuvAutonomyConfig.h` 对应参数。默认增益为零并拒绝自主 ARM，构建 AUV_A0 不会自动完成标定。
4. 填写完整 IMU 转换、阶段相机模型、实际扫描航点、上浮格与目标深度、机体包络和退出净空。未知项不能用通过标志替代；已有 ROV 定深参数不能直接证明自主控制极性。
5. 在 Pi 使用实际程序执行 `auv_runtime --check-config <实测配置>`，再无动力检查双摄、遥测、记录和安全门。配置校验通过只说明配置合法。
6. 局部闭环修复并复测通过后，才进行有动力分阶段试验；现场显式 ARM，随时能独立切断推进器动力。当前无漏水检测，密封需人工检查。

Pi 关机或维修时无法确认设备身份、当前参数及实时门控。此入口不部署、不烧录、不连接 UART、不发送 START/ARM；不修改生产安全门或实测配置。
