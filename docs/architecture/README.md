# 架构与模块边界

本目录整理系统架构、模块职责和总体代码边界，适合在阅读实现代码前先建立全局视图。

## 目录内容

- [repository-layout.md](./repository-layout.md) — 仓库布局与模块边界

## 阅读建议

1. 先看仓库布局，确认每个 ROS package 和工具目录的职责。
2. 再结合根目录 [README.md](../../README.md) 的系统架构图，理解 PC/Pi/STM32 三层职责。
3. 若要进入具体实现，再按 `src/auv_*` 对应模块继续阅读。

## 关键原则

- Linux / ROS 2 侧只负责高层计算与任务编排，不承担实时姿态 PID。
- STM32 负责实时闭环、推进器混控、heartbeat 和 failsafe。
- ROS package 的边界必须保持清晰，避免把算法、传感器驱动和任务状态机耦合在一起。
- 硬件参数和接线应以真实设备和配置为准，不在代码中硬编码未验证值。
