# 轻量 AUV 功能完整性检查（2026-10-07）

## 结论

当前为 ROV 实机控制基础加任务一软件链路，不是可完成全部竞赛任务的 AUV。检查以当前工作区源码与配置为准，不代表树莓派实时版本；近期 SSH 超时，本轮未执行 ARM、运动、烧录或部署。未运行完整 Linux runtime 回归。

## 功能覆盖

| 功能 | 轻量系统实现情况 | 主要缺口 |
|---|---|---|
| 启动、自检、故障与任务日志 | runtime/FSM 已实现，支持自主启动锁存和 ARM/ACK | 当前配置为 debug，auto_start/auto_arm 关闭；绝非仅打开开关即可下水 |
| 双摄采集与回传 | CSI 下视、USB 前视、MJPEG 缓存接口 | 最新优化未部署，真实 FPS、延迟、录制问题未验收 |
| AprilTag | runtime 调用检测器 | 主要消费“找到标签”布尔量，没有标签米制场地位姿；无主动搜索运动 |
| 九宫格和圆/方锥 | 网格映射、透视变换、分类和多帧融合存在 | 外框算法要求黄色大面积四边形，与用户场地图仅黄色单边可能不匹配；需真实图验证 |
| 地图和目标路径 | A* / 目标访问顺序、路线执行器已有 | 配置方向系数为零，运动关闭；旧网格位置没有可靠场地方向、机身倾斜和安装补偿 |
| 二维相对定位 | 首版独立定位、HTTP、轨迹和回放源码已实现 | 默认关闭且未标定，未完整链接/实机验证；没有接进 RouteExecutor 或 Mission，自主原点初始化未接通 |
| 海参/海龟/海星识别 | 仓库有 YOLO/目标检测相关模块 | native auv_core/runtime 未构建或调用这些检测器；未找到仓库内 .pt/.onnx 权重 |
| 搜索、对准、抓取、运输、释放 | FSM 阶段和爪命令/ACK/状态接口存在 | runtime 不更新 cucumber/transport 感知事件，无相应运动策略；爪未标定 |
| 转盘识别、对准、旋转 ≥180° | 检测模块和 FSM 状态存在 | native runtime 未接检测和操作；没有转角/完成量闭环，无法验收180° |
| 返航和上浮 | FSM 有 RETURN_HOME/SURFACE | runtime 不更新 home/surface 事件，无返航路线或上浮目标生成 |
| 独立长期视频采集 | PC DatasetRecorder 已实现 | 脱离 PC 的 AUV 尚无训练视频长期本地录像服务；HLS 回传不是原始数据留存 |

## 直接阻塞项

1. `AuvRovConfig.h` 的 `AUV_ROV_MANUAL_TRIAL=1`；`AuvLink.c` 在此模式对 MOTION_TARGET 返回 UNSUPPORTED，ARM 还依赖 RC 许可。必须保留 ROV 配置并单独建立、验证 AUV 配置，不能直接替换已验证手柄固件。
2. runtime 配置串口为空、运动关闭、方向/限幅未确认；STM32 绝对深度控制标定门关闭。ROV 相对定深有效不能证明 AUV 深度目标控制有效。
3. `full` 只是令 FSM 在遍历交通锥后进入 SEARCH_CUCUMBER。runtime 未调用 update_cucumber/update_transport/update_valve/update_home/update_surface；这些事件只在 FSM 单元测试里人工注入。后续阶段会等待到超时。
4. RouteExecutor 只在 VISIT_CONES 激活，消费旧 row/col 网格位置。新 localization 输出仅用于显示和记录，还不能驱动自主导航。
5. AprilTag 搜索和初始建图阶段没有覆盖全场的搜索策略。当前基本依赖目标已经出现在相机画面中。

## 场地与导航风险

GridMapper 对黄色 HSV mask 找闭合四角外轮廓，再检查内部分割线。若真实场地如示意图只有底部黄色基准边，黄色 mask 本身不会形成所需外框，BUILD_MAP 可能一直失败。应改为黑色网格/外边缘检测，黄色单边用于辨认方向，并通过真实水下视频回放验证。

当前 grid pose 使用图像中心的透视映射并夹到0..3，不等于机器人中心的米制定位，也不能可靠区分机器人在外框之外。路线 row/col 到 surge/sway 是固定线性映射，没有跟随当前航向转换。这些问题需要在接入新定位时解决，不能把当前新定位 API 有结果当作导航已经闭环。

## 建议完成顺序

1. 修复双摄与录制、取得真实场地录像；完成池深、深度零点、相机和安装标定。
2. 完成轻量 runtime 整体构建/回归；验证真实场地网格算法及相对定位。
3. 建立独立 AUV 固件/配置，验证目标协议、深度和航向控制，保持默认 DISARM。
4. 将定位会话、质量与航向转换接入导航；实现启动原点、主动搜索、路线停止/恢复及任务一水下验收。
5. 加入返航/上浮，先完成一个自主任务闭环。
6. 依次接通前视目标检测、对准抓取、运输释放、转盘控制和转角验收；补齐脱离 PC 的本地记录。

已有虚拟 STM32 和合成视频测试是软件验证，不证明真实推进器方向、真实场地识别或完整比赛流程。建议按阶段验收，不给整个系统一个容易误导的“完成百分比”。
