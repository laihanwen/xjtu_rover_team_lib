# 标签接近测试逻辑与可行性复核

复核日期：2026-10-09。范围为当前工作区的标签测试状态机、Runtime 接入、模板、MCU 运动入口与软件测试；未连接实机、部署、烧录或 ARM。

结论：源码已有条件完整的反馈状态链，但当前模板不具备执行条件，且悬停保持判据、双摄交接与完整原生验证仍有缺口。不能将虚拟驾驶台演示视为动力学或闭环测试结果。

## 已有闭环

`INIT → WAIT_ARM → DEPTH_TEST → FRONT_APPROACH → DOWN_CENTER → HOVER`。

- 启动要求新鲜前视 ID 18 米制观测、连续下视定位原点、独立深度样本、双摄采集、记录就绪及 MCU 安全状态。双模式固件处于 ROV 时不能用于 AUV 执行。
- 深度目标依次为 0.8 / 0.6 / 0.7 m，目标变化率 0.03 m/s。独立深度序列更新、误差不超过 0.03 m、稳定至少 2 s 并累计至少三个样本才报告与推进；并有阶段超时。
- 前视使用标签 PnP 加实测外参，平移向量按距离比例、绝对上限和变化率限制。下视同 ID 连续三帧有效可接管，包括深度测试结束时标签已经在下视的情况。
- 下视中心误差不超过 10 px、持续至少 2 s 才进入 HOVER。保持工作深度和 ARM；超过 15 px 恢复位置修正，回到 10 px 内停止平移。
- 观测失效立即清零平移；持续丢失超过 2 s、定位过期/失去连续性、超出走廊、深度越界、安全门失效及人工停止进入 FAULT 并请求 DISARM。故障不会自动重新启动。
- 双路机载原始录像、深度报告、事件、轨迹与居中证据保留。HOVER 故意不使用接近阶段总超时。

## 主要缺口

### P1：当前模板不能执行

串口为空、运动关闭、前视内参标记为试验值；定位外参、池深、深度零点配套实测、双摄外参、走廊半径和验证标记未完成。配置加载器明确拒绝直接开启运动。平面光流需要真实池深计算米制尺度；1.2 m 是允许作业深度上限，不能代替池深。

启动深度必须在 0.1–1.2 m 内，因此当前流程要求机器人已浸入并满足视觉/定位条件，不能从水面深度约零直接开始自主下潜。深度测试只检查三个定深点的跟随与稳定，不测池底深度。

### P1：双摄交接遇到无重叠盲区会停止，可能无法完成接近

前视阶段没有“依据最后目标继续通过盲区”的运动，也没有标签消失后的另一种绝对定位接近策略。前视不可用且下视不足三帧时平移立即为零，超过 2 s 进入 FAULT。停止行为正确，但若几何上无法在停车位置获得下视标签，任务将不能自行完成。

人工搬运屏幕录像的每秒样本没有双路同时识别，不能证明不存在重叠，也不能证明有可靠交接。需要固定真实舵机角、相机外参和作业高度后测量连续可见区。不能以延长丢失超时或盲目前进替代验证。

### P1：HOVER 未监督持续深度/航向跟随误差

定深与定航向输出持续交给 MCU，但 HOVER 的任务判据只监督标签位置、定位、安全门、深度范围与横滚/俯仰。深度在允许范围内长期偏离 0.7 m，或航向长期偏离目标，没有任务级跟随误差计时/故障判据；标签仍居中时仍可能显示 HOVER。首次进入 HOVER 也未再次要求深度、航向共同稳定。

这不代表没有 MCU PID；缺少的是任务层对保持结果的验收与异常升级。建议新增经实测配置的深度/航向稳定门、偏差持续时间、报告与故障测试，保留启动瞬态容限。

### P2：调试启动与 ARM 超时耦合

`start` 进入 WAIT_ARM 后仅等待 5 s，计时起点是任务启动，而非操作员发出 ARM 请求。人工检查监视台再确认 ARM 很容易超时，之后必须新建进程会话。应区分“等待操作员确认”和“已发送 ARM 等待 MCU 确认”，保持显式 ARM，不自动延长或绕过 MCU 门控。

## 验证范围

本轮重跑现有 Windows 固件主机 CTest 17/17 和模式交接 Python 测试 4/4，均通过。它们验证固件/交接软件保护，不覆盖当前完整 Runtime 标签任务。

最新标签几何、状态机与 PTY 双摄端到端测试仍缺 Linux 原生编译执行证据。此前端到端测试曾因定位新鲜度保护失败，后续模拟素材/悬停修正尚不能宣称已全部通过。Windows 当前没有 OpenCV C++ 开发包，不能用 Python cv2 或前端模拟代替。

建议顺序：先补任务层保持判据与 ARM 等待语义；完成 Linux 编译及完整 CTest；再完成固定角度前视标定、双摄外参、池深/零点和运动符号；离线真实视频验证连续交接；最后无动力验证协议与故障，再受控水池执行。当前不建议直接开启运动下水。
