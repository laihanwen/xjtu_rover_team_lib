## 流程与证据

`INIT → WAIT_ARM → DEPTH_TEST → FRONT_APPROACH → DOWN_CENTER → HOVER`；异常进入 `FAULT` 并请求 DISARM，不自动重试或重新 ARM。

1. 自主模式通过静止定位原点、两路图像、遥测、压力计独立采样、记录及姿态安全门后，使用已有一次性启动锁存。调试模式显式 start 后还需显式 ARM。
2. 保持启动航向，平移为零，深度目标以 `0.03 m/s` 的设定值变化率依次到达三个深度。这是深度设定变化率，不是机器人实际垂向速度。每点允许误差 `0.03 m`，至少三次独立压力计更新并持续稳定 `2 s`；每阶段超时 `30 s`。
3. `DEPTH_TEST_REPORT` 汇报目标、实测均值/最小/最大、样本数与均值误差。不能根据这些结果宣称池深已测量或绝对深度已标定。
4. 前视在矫正像素上检测同一标签，经 138 mm 平面 PnP、正深度、池底平面方向及最大重投影误差 `2 px` 检查后转换到机体坐标。规划器计算使下视画面中心落到标签上的局部直线目标，并根据每次新观测修正；这不是带障碍物地图的 A*，只适用于实测无障碍的接近走廊。
5. 前视连续三帧确认后才允许前视引导的平移；下视同 ID 连续三帧确认后优先接管。深度测试后若标签已经出现在下视，不要求重新在前视找到它。下视画面中心为 `(width/2, height/2)`，不把主点当作画面中心。目标失去有效观测立即停止平移，超过 `2 s` 终止，不在双摄盲区按旧位置继续前进。因此需要真实验证交接视野重叠。
6. 下视中心误差不超过 `10 px`、持续 `2 s` 且存在新帧，进入 `HOVER`，继续保持 ARM、第三个深度目标 `0.7 m` 和启动航向；偏离中心后根据最新下视观测恢复限幅平移修正，回到中心误差范围后停止平移但继续定深/定航向。接近阶段的 90 s 超时不终止已建立的悬停；悬停持续到操作员显式 `abort` / `pause` / DISARM，或安全门失败。保存用于进入悬停判定的矫正图 `evidence/tag18-down-centered.jpg` 及对应帧序号、时间、标定版本 YAML。该证据单独保存，实时下视缓存持续更新，不把进入悬停时的图像冻结后用于后续控制。

全程保留双摄原始录像、帧索引、定位事件，`TAG_DOCK_TRACE` 每 0.2 s 记录实际相对位姿、规划目标、深度/目标、独立深度采样序号和双摄帧号。只读 `auvctl status` 的 `tag_docking` 字段提供最近深度报告与观测状态。目标运动单位是现有协议归一化量，`maximum_target: 0.08` 不能解释为 m/s。

## 编译产物与启动入口

Windows 构建独立 STM32 工程，不覆盖 ROV HEX、不烧录：

```powershell
./tools/auv/Build-AuvFirmware.ps1 -Profile AUV_TAG_DOCK
```

产物 `firmware/stm32/MDK-ARM/AUV_TAG_DOCK/AUV_TAG_DOCK.hex`。仅设置自主配置选择和最大深度 `1.2 m`；原有 commissioning、深度校准、输出增益与方向门仍保留。

用户明确授权烧录时，使用独立入口，包含烧录前备份和全 32 KiB 回读：

```powershell
./tools/auv/Flash-AuvFirmware.ps1 -Profile AUV_TAG_DOCK
```

Linux 构建与只读配置校验：

```fish
cmake -S . -B build-native -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build-native -j 3
ctest --test-dir build-native --output-on-failure
build-native/runtime/auv_runtime --check-config runtime/config/pi-auv-tag-docking.yaml
```

默认配置是 debug、运动/自动启动/自动 ARM 关闭、串口留空；可作为双摄识别与录像入口，不能据此直接自主游动。`auv-tag-docking.service` 是独立模板，默认不安装、启用或替换现有 ROV 服务；与其他控制服务互斥。

已有 Pi 完成构建与测试后，`runtime/deploy/deploy_tag_docking.sh` 可在该源码目录以 root 执行。需先提供当前 HEX SHA256 文件 `firmware-tag-docking.sha256` 及提交文件 `release-commit.txt`。脚本按程序校验生成独立 `/opt/auv-tag-docking/` 发布目录，保留旧服务启用/运行状态与配置，接管串口并启用 AUV 待命服务。部署配置沿用实测双摄配置，串口 `/dev/serial0`，监视台绑定 `192.168.137.150:8080`，保持运动、自动启动、自动 ARM 关闭。原 ROV/Runtime 服务停止并禁用自动启动，源码和旧发布程序保留；不要用 ROV 维护脚本覆盖这个独立 AUV 发布。

监视台为只读，显示深度、双摄中心标记、标签发现/几何有效性、任务阶段与最近深度报告。标定验收后，调试入口先请求 `auvctl start` 进入 WAIT_ARM，再由操作员显式请求 `auvctl arm --confirm SAFE_TO_ARM`。这些命令可能使推进器动作，部署脚本不会代为执行。未验收配置会拒绝 start/ARM。

实测参数补齐、无推进器动力联调通过后，自主发布配置使用 `operation.mode: autonomous`、`auto_start: true`、`auto_arm: true`。这是一份后续运行配置要求，不代表本次已经 ARM 或下水。

## 尚需实测的参数

- 前视当前 `provisional_unstable_intrinsics` 仅供试验显示，不能用于自主米制导航。需独立验证前视内参，更新 K/D 与标定版本、质量 `independently_verified`；仅改质量字符串不算验证。
- 两相机的 `camera_to_body`（光学坐标到 X 前/Y 左/Z 上的正交旋转）与机体安装偏移；下视几何必须与定位配置完全匹配。PnP 输入复用已矫正帧，使用对应 K 和零 D。
- 池底水深、压力计位置、IMU 符号/偏置、绝对深度水面零点和定深修正方向；当前配置中的空数组与 0 必须用实测结果替换，不能自动猜测。
- 无障碍走廊及起点最大半径；运动方向、协议目标到 PWM 增益、最大输出与现场急停。在 MCU `AuvAutonomyConfig.h` / `AuvRovConfig.h` 对应实测项完成前，独立固件会拒绝自主 ARM。
- 深度目标的机体净空；模板最小允许深度 `0.1 m` 和姿态上限 `0.15 rad` 为初始保守限制，仍需现场确认。启动实际深度须在允许范围内。

配置开启运动时检查上述标记、独立前视质量、录制、定位、两路矫正及安全走廊。最大深度不得超过用户指定 1.2 m。失效、越界、定位会话变化、意外 DISARM、持续标签丢失和接近阶段超时都终止任务。悬停短时丢失标签先停止平移并维持定深/定航向；超过 2 s 仍不能恢复则进入 FAULT 并 DISARM。恢复观测仍需三帧重新确认。

## 人工搬运录像复核与控制调整

2026-10-09 复核用户提供的 `屏幕录制 2026-10-08 232851.mp4`，时长约 145 s，1460×484、30 FPS。它是双摄预览的屏幕录像，无同步深度、姿态或推进器输出；不能据此辨识动力学、标定外参、测量真实移动速度或宣称悬停稳定。

逐段视觉检查可见：下视标签较大并有贴近边缘、出画面和搬运转动；前视标签较小且透视倾斜、存在人员遮挡。采用与 Runtime 一致的 tag16h5 字典和 AprilTag 角点细化，每秒抽样裁剪两路预览并近似映射到 320×240：下视 10 帧识别到 ID 18（主要 19–42 s），前视 21 帧（86–130 s），样本中没有双路同时识别。该抽样不证明不存在短暂重叠，也不证明连续检测率；屏幕裁剪与再编码会影响检测和像素尺度。

据此增加任务专属参数，均为待实机验证的保守初值：

- 最短标签边至少 `8 px`、全部角点距图像边界至少 `3 px` 才进入米制控制。小目标、强透视压缩或截断目标保持“发现”状态，但不允许用于运动。
- 平移归一化向量上限：前视 `0.08`、下视 `0.04`、悬停 `0.03`。向量每秒变化上限 `0.08`；失效、丢失、居中停车不受缓变限制，立即停止平移。不是 m/s 或物理加速度。
- 悬停中心误差 `≤10 px` 停止纠偏；只有 `>15 px` 才重新纠偏，开始纠偏后回到 `≤10 px` 停止，避免在边界反复动作。新鲜三帧仍为交接/重获门控。
- 下视有可靠同 ID 观测时直接优先接管；悬停只用下视闭环，不在遮挡后切回前视追逐。双摄均失去可用观测时仍停车，不根据录像猜测盲区长度或延长开放环前进。

可用 `tools/auv/review_tag_video.py` 重复离线复核；需要独立 Python OpenCV/NumPy 环境。本次参数为 `--down-roi 86,42,536,402 --front-roi 816,42,536,402 --sample-hz 1`，输出到忽略的 `build/tag-docking/video-review/report.json`；ROI 是当前屏幕布局的近似值，不能套用到其他录像或用于标定。工具不重复去畸变、不访问 UART、不输出运动指令。录像与图片未加入 Git。

新增回归覆盖小标签/截断拒绝、直接下视接管、平移变化率、悬停输出上限和中心误差迟滞。录像离线分析、Python 语法与 Git 空白检查已完成；Pi SSH 仍超时，最新 C++ 及端到端模拟尚待原生编译复测。ROV 固件、遥控驾驶台与控制映射本轮未修改，未部署、烧录或 ARM。
