## 2. 比赛任务映射

| 转盘15分 | 自主接触驱动5分；黄色胶带相对初始方向≥180°且最终稳定10分 | 红色中心用于对准；跟踪黄色单侧标志。执行器转动量不能替代转盘实际角度 |
| 返回结束5分 | 返回右下投放区并浮出水面 | 确认位于投放区，再上浮；正常结束与故障回收分别记录 |

完整顺序遵循2.1：投放 → 中心标签 → 建图 → 上浮遍历 → 右上海参 → 左下投放 → 左上转盘 → 右下返回上浮。任务一阶段验收是研发里程碑，不宣称它已满足正式全赛流程。完成全部节点前，不把任务二跨场导航当成已授权比赛策略。

## 3. 系统与算法边界

### 运行架构

- 比赛主入口为 Pi 4B 的原生 `auv_runtime` + 共用 `auv_core`，STM32F405负责实时姿态、深度、混控与保护。ROS 2 Lyrical保留为开发、调试和回放入口，不作为轻量比赛进程的必需依赖。
- 保留现有八推硬件和已实测控制基线，不因早期六推建议重新设计混控。建立独立AUV固件构建/配置与发布记录，复用已验证模块；不能直接覆盖ROV基线。
- Runtime独占UART；双摄单一采集所有者，导航、检测、录像复用帧缓存。视觉、网络、编码和写盘不能阻塞控制与心跳。
- 正式模式无安全缆、通信缆、供电缆，使用机载电池。只允许一次启动或任务选择；不依赖手柄、SSH、远程reset、在线PC推理或岸上外部定位辅助得分动作（2.3）。调试模式可联网，正式模式关闭普通控制入口；保留可靠本机急停与符合现场规定的回收措施。

### 定位与导航

- 以结构化场地二维坐标、深度与航向为最小导航状态。采用已知池底平面、下视视觉相对里程计、IMU，以及可见网格/标签的场地约束；优先验证这些约束能否抑制跨场漂移。
- 区分场地坐标、连续里程计坐标、机体坐标、相机坐标；原点、黄色边方向、安装外参和场地尺度均需实测。相对原点不是自动等于比赛投放区或网格原点。
- 当前定位模块只是诊断入口；必须接入导航的新鲜度、有效性、连续性和session检查。失效先停止平移；仅在有可信位姿条件下限时自主重定位。无法恢复进入故障回收，不凭旧位姿盲行，也不要求操作者赛中重置。
- 水下平面视觉里程计不能直接覆盖水面遍历：中途上浮后相机距底、姿态、反光和深度读数工况均改变。必须单独验证水面定位，并在水下/水面切换后重新观测场地基准；光流积分不能无条件跨越该阶段。
- 当前平移是开环推力，不是有实测反馈的m/s速度闭环。导航用位置/图像误差生成限幅平移目标，STM32继续闭环深度与航向；控制接口单位及符号须明确。
- 4目标顺序直接枚举24种，格间使用A*。增加“已访问目标格不可再次穿越”约束，模拟完整路径中的提前经过目标与重复进入，并含起点、出口；必要时使用含访问位集的有限状态搜索。无合法路线要报告原因，不能返回普通最短路冒充合规路线。
- 四区域间采用配置化航点/走廊、局部视觉对准与道具净空约束；不扩张成未知海域自主探索。

### 感知与操作

- 下视CSI：AprilTag、黑色网格、黄色方向边、锥轮廓、相对定位。黄色边只提供方向，不要求黄色闭合四边形。先验证OpenCV规则方法在伪装纹与真实水下成像中的可靠性。
- 地图保存完整格子、类别、实际检测轮廓/截图、相对位置、方向依据与质量；多帧确认后冻结任务一地图。未知不能默认为空，抽签模板不能替代观测。
- 前视USB：海参/干扰物、近距离对准、抓取效果、转盘中心与黄色标志。YOLO11n优先，只选ONNX Runtime或NCNN一种经Pi实测可用的部署路线；训练环境保持隔离。
- 抓取采用“搜索 → 对准 → 接近 → 抓取 → 验证持有 → 运输 → 框内释放 → 验证落点”的有限状态闭环；多次抓取有次数/时间上限和去重。机构容量与力矩由实物试验决定，不默认一次收纳5只。
- 转盘采用“找到 → 对准 → 接触 → 转动 → 脱离/停止 → 观察稳定”的闭环。保存初始、过程、最终图像及带方向的角度；避免用十字对称轴或90°包角误判180°。回弹后不足不得判完成。
- 当前未装漏水传感器，不伪造漏水检测能力；电气急停、通信与传感器失效、限幅、启动中立及显式ARM必须成立。自动任务的ARM是预先配置的一次性启动流程中的受控请求，仍须MCU安全门接受，故障后不自动重ARM。

### 数据与资源

- 原生入口机载保存视频分段、帧时间索引、遥测、任务事件、地图快照、计划与实测轨迹、节点进入/退出、抓取持有/释放证据、碰撞或疑似碰撞、转盘角度及最终状态。没有碰撞传感器或可信视觉证据时，标注未确认，不能宣称零碰撞。
- 每次任务使用run_id，记录提交号、HEX校验、模型校验、配置与标定版本；统一单调时间用于排序，有墙钟则同时记录。丢帧、断流、写盘失败、磁盘余量均显式记录。
- Pi预算以双摄+定位+检测+录像同时运行实测为准。采用有界队列、最新帧策略、限频和分段写盘；先保障控制新鲜度和核验数据，再安排预览质量。不能把目标FPS当实测性能。

## 4. 后续开发阶段

| 阶段 | 实施内容 | 退出条件 |
|---|---|---|
| A0 自主基础 | 独立AUV配置、运动协议与控制权、绝对深度标定、自动原点与启动、急停与机载录像 | 离线/主机故障测试、固件编译、无推进器动力联调通过；受控水池验证目标方向、超时停机、深度与航向，PC断开不影响记录 |
| A1 场地观测 | 真实水下双摄数据、内外参、标签主动搜索、黄色单边网格、4锥轮廓地图 | 多种公布摆放回放及水池验证；黄边向下、4锥类别位置可复核；无标签不触发建图 |
| A2 任务一闭环 | 进入中心、完整建图、中途上浮、水面定位、无重复路线、机载节点与实际轨迹记录 | 从投放区一次启动完成；按实测进入格确认4节点；多次重复试验，报告成功次数/总次数与定位误差；不把FSM COMPLETE等同全赛结束 |
| A3 跨区与回收 | 养殖区/收集区/转盘区/投放区航点、净空、重定位、返航上浮 | 先无载荷验证跨区、回到投放区才正常上浮；定位失效与任务超时能安全终止 |
| A4 一只到五只海参 | 接入前视推理、抓取机构标定、持有判断、红框定位、投放核验 | 先一只自主闭环，再增加次数/容量；最终框内数量与证据一致，不把干扰物计入；运输不依赖PC |
| A5 转盘与全流程 | 红中心/黄标识检测、真实机构操作、最终角度及回弹验证、完整FSM接线 | 最终稳定角度满足现场口径，完成任务顺序、返航上浮和赛后材料；全流程计时、热负载与故障演练通过 |

优先A0-A2，跨场定位方案在A1期间并行做离线验证，避免任务一后才发现无法抵达四角。上表不授权自动烧录、ARM或推进器动作，实机试验按现有维护与安全流程执行。

现有 `full` 后续感知、运输、转盘、home/surface事件仍需真实闭环接通。A0/A1/A2 已增加独立自主观测与任务一入口，按阶段接通搜索、中心对准、上浮、表面重定位和遍历；详见 [A0/A1交付](auv-a0-a1-implementation.md) 与 [A2交付](auv-a2-implementation.md)，未完成下水验收。跨区控制不可直接全局放开。定位文档记录Pi已编译部署诊断但未标定有效；旧完整性报告中的“尚未部署”不作为当前定位状态结论。

## 5. 暂不纳入

通用SLAM/三维稠密重建、复杂VIO、DVL/声呐硬件升级、强化学习/遗传/蚁群规划、micro-ROS、Pi高速姿态PID、大型YOLO、完整ROV界面重做、全仓库重构，以及无需评分的交通锥朝向估计。只有实测证实轻量方案不能满足某项验收，才针对该瓶颈重新评估。ROS功能数量和节点数量不作为AUV进度指标。

## 6. 赛前必须澄清的边界

1. 2.1明确“建图完成后上浮遍历”，须确认是完全水面航行还是指定浅水高度；不能直接照搬水下定深遍历。
2. 2.5使用“全程未重复遍历任一交通锥节点”，但2.1又允许运输穿越中心。须确认不重复的判定只限任务一还是含运输，以及初次搜索/建图经过是否计入。澄清前保留全程进入/退出记录，后续路线优先绕开已访问目标格。
3. 2.2举例含海胆，2.4明确海龟/海星，评分举例又含小鱼；以现场模型清单决定负样本，不认为三类别涵盖所有干扰。
4. AprilTag字典、ID、尺寸/朝向、网格/区域/池深尺度、允许摆放模板、转盘轴向/阻力/转角容差、海参尺寸/重量、红框边界均待官方参数或实测，保持可配置。
5. 规则给出总分145，但本文件未给固定总时长；不可沿用其他比赛20分钟。需确认时间上限、允许跳过/部分任务选择、任务二终止条件与失败后的返航计分。研发可以设置阶段预算，不能写成官方计时规则。
6. 确认赛前一次启动方式、正式模式可保留的只读通信及安全急停方式。系统按无岸上依赖实现，不把现有联网ROV试验模式当合规正式模式。

这些澄清不阻塞安全基础、离线感知、记录和标定；会影响比赛状态机及最终验收，确定后应更新本文件和任务一测试流程。
