# 水下摄像头标定：2026-10-08 筛选图片

素材：桌面 `标定板/下视图片`（218 张）和 `标定板/前视图片`（164 张）。
Q12-240-15：15 mm 方格，12×9 方格，11×8 内角点。
使用 OpenCV pinhole / plumb_bob 五参数畸变模型；未更改运行中的 ROS 配置。

## 下视结果

- 图像尺寸：320×240。
- 检出完整棋盘：159 张；按角点位置去除相近姿态后 146 张。
- 训练：116 张；留出验证：30 张；训练离群剔除：0 张。
- 训练重投影 RMS：0.092945 px；留出验证 RMS：0.089784 px。
- fx=413.292309，fy=418.541728，cx=159.539371，cy=95.115907。
- D=[0.674561076, -0.709922636, -0.070178942, 0.000809006, -0.071240982]。

`down/camera_info.yaml` 是 ROS CameraInfo 格式；`down/ros_parameters.yaml`
对应本仓库 AprilTag 和 mapping 的参数格式。完整来源、逐帧误差及参数标准差见
`down/report.json`。桌面 `标定结果_筛选图片/down` 还包含六张左右对比预览、
NPZ 参数和 `rectified_images` 中全部 218 张矫正图片。
预览左侧标注原始角点，右侧为 alpha=0 的矫正图；右图使用新的 K。
原始图像配原始 K/D；矫正图像配 rectified_camera_matrix 和零畸变，避免重复矫正。

这是同一采集批次的留出验证，不能代表独立距离、水深和整个视场的测量精度。
棋盘在许多图片中较小，低重投影误差不能单独证明图像边缘矫正准确。
水下折射由此模型近似；建议再用独立图片和已知尺寸目标验证。
参数仅适用于相同镜头、焦距/对焦、密封舱窗口和水下配置。
当前 ROS 摄像头默认 640×480，不能直接照填这些 320×240 参数。
仅当确认是同一完整视场的纯等比缩放时才可按尺寸比例缩放 K；
裁切、不同传感器模式或未知采集链路应重新标定。

## 前视结果

后续前视视频重新筛选得到试验标定参数和 40 张筛选帧，但模型稳定性不足。
最新结果及限制见 [前视视频报告](front-video.md)。以下为此前图片批次的结论。

增强对比度、2×/4×放大及交换棋盘方向后，仅一张检出完整 88 角点。
未生成前视内参，不可套用下视参数。检测记录在桌面结果目录 `front/detections.json`。
需补拍完整棋盘、足够清晰且覆盖画面中心/四周的素材，建议至少 20–30 张不同位置、
距离和倾角的照片；尽量使用摄像头原始分辨率。

## 复现（Ubuntu fish，已有隔离视觉环境）

```fish
python vision/calibrate_underwater.py /path/to/下视图片 /path/to/results/down --cols 11 --rows 8 --square-mm 15
```

依赖：numpy、opencv-python-headless、pyyaml。Windows 本次使用仓库独立
`.calibration-venv`，没有修改系统 Python 或训练环境。

标定 API 参考：https://docs.opencv.org/4.12.0/dc/dbb/tutorial_py_calibration.html
