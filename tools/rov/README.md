## 当前：低速手动试用

当前固件 `AUV_ROV_MANUAL_TRIAL=1`，Pi服务使用 `trial_server.py`；PC入口 `Start-RovTrial.ps1` / `trial_control_web.py`。**不要用旧Rover.py的A5发送方式连接这个新服务。** 当前控制页 <http://127.0.0.1:8767/>。完整部署与边界见 [手动试用记录](../../docs/reviews/rov-manual-trial-20261006.md)。

Windows重新启动：在本仓库执行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/rov/Start-RovTrial.ps1`，独立pygame依赖沿用本机 `build/joystick-deps`。网页仅监听本机，树莓派TCP绑定192.168.137.150:8888。

1. 四轴回中，左肩拨到允许位（实测axis5 ≥ +0.5）；网页显示“左肩许可：允许”。
2. 点击“ARM · 低速试用”，无固定运行时限；先逐轴小幅试动，确认实际方向。不会自动ARM或在重连后恢复运行。左肩许可、STOP、通信和惯导超时停机仍有效。
3. 左肩拨回其余位置、点击停止或按Esc停止；网页关闭/手柄掉线/网络超时也停止。硬件急停仍是最终停机手段。

当前禁止机械爪/摄像头舵机、定深及姿态保持，自主运动目标被拒绝；仅手动前后、横移、升沉、偏航。八推中位1488、偏移公共限幅±50计数，未宣称真实推力方向或ESC中位已完成水下标定。无漏水传感器，页面明确标出。

USART1=H30 460800；USART2=Pi CRC 115200（遥控、心跳、ARM、遥测）；USART3=M10 115200。深度实际收到 `Depth:-0.22m Temp:22.71C`，未零点标定，标准深度缓存仍判无效并回传null/NaN。**仅此手动试用模式不依赖深度闭环，因此深度无效不阻止手动升沉；IMU仍必须持续新鲜，不能用于自主定深任务。**

下面的旧A5/USART3自主入口说明仅适用于 `AUV_ROV_MANUAL_TRIAL=0` 的兼容模式。

## 合并内容

- 八推混控复用仓库实现；用户确认以代码位置为准：**T3右前下、T4左前下**。
- H30 默认只监听已配置设备，避免下发参考版已停用、位图尚未确认的配置；USART1保持460800。
- M10 严格解析完整 `Depth:1.21m Temp:25.27C` 或 `Temp=` 行，拒绝坏数字、NaN/Inf、越界深度、截断/超长行。
- STM32定深：遥控开关上升沿锁定当前深度，Pi使用现有米制depth目标；按新传感器样本和实际样本间隔积分，限幅并抑制积分饱和。失效、退出模式或DISARM清零控制状态。
- 遥控btn0锁航向、btn1锁深度，pitch目标固定0°；yaw微操方向与直接偏航一致。
- 摄像头候选CCR更新为2550..3100、启动2900，仍保持标定门关闭、限速和ARM授权；保留仓库夹爪。
- PWM先写安全中位再启动；UART错误复位半帧并重开接收，Pi通信错误撤销ARM。
- 整理PC发送/Pi转发工具，默认只显示帧；发送使用sendall、有界超时，转发只保留当前批次最新完整帧，失联停止发送。

中位1488、T2/T3极性-1/-1和姿态PID参数仍使用仓库基线。桌面版1492、极性+1/+1和负pitch/roll系数没有实机确认，未启用。该选择不代表这些参数已经通过本次实测。

## 遥控映射

2026-10-06 PC 实际连接检查、反馈系数/极性差异与 PID 问题见 [诊断记录](../../docs/reviews/rov-controller-pid-20261006.md)。`inspect_controller.py` 可只读记录原始输入及候选帧，不发送网络或串口数据。
`controller_check_web.py` 提供本机 `http://127.0.0.1:8765/` 逐项开始/完成界面，保存带物理控制标签的输入记录；相较按时间猜动作，可明确确认每项控制的轴编号和按钮。需要 pygame/pygame-ce；此界面只读取手柄，没有 ROV 控制接口。

帧为 `A5 + 10字节`。这是旧兼容协议，没有CRC或端到端指令时间戳，不能据此保证网络积压包的新鲜度；正式自主控制仍使用Pi CRC链路。

| pygame输入 | 物理控制 | 帧字节 | 固件功能 |
|---|---|---|---|
| axis0 | 右摇杆左右 | 1 | 偏航 |
| axis1 | 右摇杆前后 | 2 | 前后 |
| axis2 | 左摇杆前后 | 3 | 升沉 |
| axis3 | 左摇杆左右 | 4 | 横移 |
| axis4 | 右滚轮 | 5 | 舵机输入SA |
| axis6 | 右肩键 | **6** | 速度模式SC |
| axis5 | 左肩键 | **7** | 舵机选择SB |

右滚轮默认用文本中的候选范围-0.5..-0.1归一化到0..255，需通过 `--dial-min/--dial-max` 实测覆盖。摇杆方向沿用文本描述；发送端没有自动反向补偿，必须先离线核对帧，再拆桨核对真实运动方向。

本次 RadioMaster Pocket 的逐项记录与上表有差异：用户纠正后左肩为axis5、右肩为axis6，SA为button1、SD为button0；滚轮无变化，SE跳过。可显式选择 `Rover.py --mapping-config tools/rov/radiomaster-pocket.json` 进行预览。该配置使用右肩作为速度、左肩作为舵机选择，SA锁航向、SD锁深度；未知滚轮固定输出127、预留字节为0，并核对设备GUID。四根运动轴身份已核对，方向符号仍沿用候选，未完成实机方向验收。SD项目同时出现axis5变化，需注意EdgeTX模型可能把同一开关同时映射到多个通道。

## 串口与标定开关

`firmware/stm32/MDK-ARM/AuvRovConfig.h`：

- `AUV_UART2_M10_ENABLED=0`：默认USART2/PA2/PA3为旧遥控入口。
- 改为1：USART2接M10、115200；旧遥控入口关闭。USART3/PC10/PC11始终留给Pi CRC；不能照抄参考版把M10接USART3。此模式遥控工具不能接该串口。
- `AUV_DEPTH_CONTROL_CALIBRATED=0`：默认定深输出零，btn1不会继续手动升沉；完成深度方向、采样频率、KP/KI标定后才开启。
- `AUV_H30_CONFIGURE_ON_BOOT=0`：默认只监听H30；确认设备协议和输出位图前不要启用旧主动配置。

深度新鲜度仍为250ms。参考版注释称M10为0.5–1Hz：若实测属实，必须先提高设备更新率或另行设计慢传感器安全策略，否则会拒绝ARM/超时。禁止重复提交旧读数延长新鲜度。

旧遥控模式也需要USART3上的合法heartbeat和显式ARM，以及真实漏水/kill/IMU/深度输入。工具不会生成heartbeat或自动ARM。默认尚未接线的安全输入会阻止ARM；UART2被M10占用时需要Pi运动目标或另行设计完整遥控协议，不能同时开启旧遥控和M10。

选择旧遥控前先DISARM，停止Mission及 `/cmd_vel`、`/cmd_depth`、`/cmd_yaw` 目标发布，等待旧Pi目标超过250ms后再显式ARM；首次ARM时若Pi和RC目标都新鲜，现有仲裁优先锁定Pi。锁定后不允许运行中自动换源。ROS bridge可以继续提供heartbeat和遥测，但不得持续发布自主运动目标。

## 运行

在独立虚拟环境中安装手柄端pygame、Pi端pyserial；不要安装到系统ROS Python。

```fish
uv venv tools/rov/.venv
uv pip install --python tools/rov/.venv/bin/python pygame pyserial
# PC：只显示帧，核对轴/按钮/滚轮范围
tools/rov/.venv/bin/python tools/rov/Rover.py
# Pi：只显示接收帧，不打开串口
tools/rov/.venv/bin/python tools/rov/socket_server_new.py --bind 0.0.0.0
```

Windows手柄环境的Python路径为 `tools/rov/.venv/Scripts/python.exe`。

完成断电/拆桨验收后，PC显式加 `--send --host <Pi-IP>`；Pi显式加 `--forward --device /dev/serial0`。Pi串口必须实际接到STM32 USART2遥控入口，并确认串口登录控制台已关闭、3.3V电平和共地。服务只用于可信直连网，没有认证。默认绑定127.0.0.1，跨机器通信才显式指定网卡地址。

这些工具不读取/显示遥测；IMU/DEPTH/STATUS继续由现有 `auv_stm32_bridge` 发布。不能把界面上没有数据解读为姿态/深度为零。

## 连续水下调平恢复（2026-10-06）
用户确认T1–T8正反向均测得最低连续起转偏移±48 μs（中位1492）。退出单路标定，CRC 0x07脉冲在固件和桥接端禁用。恢复手柄平移/偏航、横滚/俯仰P=1、I/D=0、PID输出±20，角度2°进入纠正、1°以内退出。混控公共缩放到75后，小于1计数保持中位，其他需求映射为sign*(48+27*abs(demand)/75)，实际限幅±75。此补偿改变小输出推力与混合比例，不等同于水中推力标定；需观察回正方向和振荡。零需求维持1492。连续运行无固定时限，保留所有人工和失联保护。定深、航向保持、舵机关闭，CSI回传保持开启。
